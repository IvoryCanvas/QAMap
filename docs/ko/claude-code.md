# Claude Code에서 QAMap 사용하기

[English](../claude-code.md) | [한국어 문서 홈](README.md)

플러그인은 검수 스킬을 제공하고, QAMap CLI가 로컬 근거를 수집하면 Claude가
해석합니다. 로컬 저장소, Git, 터미널과 Node.js 20 이상이 필요합니다.
로컬 저장소나 터미널에 접근할 수 없는 웹 채팅에서는 실행할 수 없습니다.
Cowork나 일반 Claude 채팅에서의 지원을 보장하는 안내는 아닙니다.

## 플러그인 설치

Claude Code에서 이 저장소의 플러그인 마켓플레이스로 설치합니다.

```txt
/plugin marketplace add IvoryCanvas/QAMap
/plugin install qamap@ivorycanvas
```

마켓플레이스는 기본 브랜치의 `plugins/claude`에 있는 플러그인을 제공합니다.
`/plugin`에서 플러그인이 활성화되었는지 확인하세요. 사용 중인 Claude Code 버전의 마켓플레이스 명령은
[공식 설치 안내](https://code.claude.com/docs/en/discover-plugins)를 참고하세요.

QAMap은 [Claude 플러그인 디렉터리](https://claude.com/marketplace/plugins)에도
있습니다. **IvoryCanvas**의 **QAMap**을 검색해 해당 페이지의 설치 기능을
사용하면 됩니다. claude.ai 계정에서 활성화한 플러그인은 Claude Code 2.1.273
이상의 터미널 세션에서 같은 계정으로 로그인하면 연동됩니다. 스킬이 하나만
활성화되도록 두 경로 중 하나만 사용하세요.

## CLI 별도 설치

플러그인에는 CLI가 포함되어 있지 않으며, 자동으로 설치하지도 않습니다.
스킬에서 요구하는 버전을 사용자 동의하에 설치합니다. 0.5.1 스킬에는 다음
버전이 필요합니다.

```sh
npm install -g @ivorycanvas/qamap@0.5.1
qamap --version
```

설치할 때 npm에서 패키지를 내려받습니다. QAMap에 모델 공급자의 API 키를
등록할 필요는 없습니다. 환경에 따라 필요한 npm 인증은 패키지 매니저가
처리합니다. npm의 새 버전을 설치했다고 플러그인도 업데이트되는 것은 아닙니다.

## PR 검수 요청

검수할 브랜치에서 Claude에게 다음과 같이 요청하세요.

```txt
이 PR에 버그가 없는지 확인해줘.
```

저장된 선택이 없으면 스킬이 QAMap 사용 여부를 묻습니다. 이번만 사용하거나,
앞으로도 사용하거나, 지금은 사용하지 않을 수 있습니다. 설치만으로 분석에
동의한 것으로 보지는 않습니다. 거절하면 QAMap은 해당 변경을 분석하지
않습니다. 대화에서 QAMap을 직접 요청해 한 번만 사용할 수도 있습니다.

동의 후에는 검수 브리프를 한 번 실행하고 완료를 기다립니다. Claude는
브리프에 담긴 diff, 테스트, 호출 코드, QA 항목과 미확인 내용을 읽습니다.
기본 명령은 분석 전에 저장된 동의를 확인합니다.

```sh
qamap qa brief --require-consent
```

이번만 사용하겠다고 명시적으로 동의하면 스킬이 해당 옵션을 빼고 실행할 수
있습니다. 계속 사용할지 직접 설정하려면 필요한 범위와 작업에 맞는 명령을
하나 선택하세요. 아래의 모든 줄을 설치 순서처럼 실행하지는 않습니다.

```sh
qamap consent grant
qamap consent grant --global
qamap consent status
qamap consent revoke
qamap consent revoke --global
```

`grant`는 현재 프로젝트에 적용하고, `--global`은 지원되는 사용자 지침에
적용합니다. 이 설정은 테스트 실행, 코드 수정이나 설치를 허용하지 않습니다.
별도로 허용한 명령을 실제 실행하기 전까지 테스트 상태는 `not-run`입니다.

## 디렉터리 설치 없이 사용하기

CLI를 설치한 뒤 프로젝트에 스킬과 지침을 추가하려면 다음을 실행하세요.

```sh
qamap init --agent .
```

기존 내용을 보존하면서 QAMap 전용 지침 구간, 프로젝트 스킬과 초기 설정을
추가합니다. 디렉터리 플러그인 설치가 아닌 프로젝트 설정 방식이며, 이 경우에도
분석 전에 동의를 확인합니다. 저장된 선택과 다른 호스트의 사용법은
[에이전트 연동](agent-integration.md)에서 확인할 수 있습니다.

## 토큰, 보고서와 업데이트

QAMap의 분석은 모델을 호출하거나 소스를 업로드하지 않습니다. 하지만
Claude가 스킬을 읽고 실행을 요청하거나 결과를 해석할 때는 모델 토큰을
사용합니다. 완료를 확인하려고 모델을 추가로 호출하면 사용량이 늘지만,
대기 시간이 길다는 이유만으로 토큰이 드는 것은 아닙니다.
반환된 코드 발췌는 호스트의 데이터 정책에 따라
모델 문맥에 들어갑니다. 브리프는 반복 탐색을 줄이는 방식이지, 토큰 절감이나
모든 버그 발견을 보장하는 기능은 아닙니다.
[실측과 한계](../release-validation.md)는 플러그인 승인과 별개의 검증입니다.

전체 보고서는 기본적으로 `~/QAMap-reports/qa-*`에 저장됩니다. 비공개 코드나
저장소에 이미 있는 개인정보가 포함될 수 있으므로 보관과 공유 여부를 직접
관리하세요. 보고서 저장은 테스트 통과를 의미하지 않습니다.

npm, OpenAI와 Claude 디렉터리 버전은 각각 업데이트됩니다. 플러그인을
업데이트한 뒤에는 요구하는 CLI 버전도 확인하세요. 관리자의 업데이트 절차는
[Claude 제출 안내](../claude-plugin-submission.md)에 정리되어 있습니다.
