# 0.5.0 Release Preparation

**Candidate: `0.5.0-rc.1`. Not published. Stable `0.5.0` remains on hold.**

This candidate combines reusable repository evidence with an opt-in report-review
workflow. QAMap stays local and makes no model calls. An agent invoking QAMap and
interpreting its output still consumes tokens.

## Scope

- Reuse supported JS/TS syntax evidence and trace declared cross-package links.
- Save local reports with `qa report`; add `--handoff` to return bounded evidence.
- Preserve declaration, import, consumer and assertion context, including deletion
  boundaries and distant expectations, within a 16,384-byte response.
- Store a user's explicit project choice with `init --agent --review-mode report`;
  use `--review-mode ask` to revoke it. Installation alone is not consent.
- Keep tests `not-run`, missing evidence unknown, and execution separately authorized.

## Compatibility And Migration

Existing `qa`, `qa run`, agent-format and receipt-only output remain available.
The existing `qamap.qa` v1 summary retains its 4,096-byte limit. The separate
`qamap.qa.handoff` v1 envelope may contain up to 16,384 bytes; consumers must not
apply the summary limit to the full handoff. No manifest migration is required.

The candidate skill requires the matching candidate CLI. Do not pair it with
0.4.17 or install a missing version automatically. Test the local tarball first.
After approval and npm publication, verify the exact registry version before
uploading its separately versioned plugin bundle. Existing directory installs do
not update merely because npm or GitHub was updated.

## Evidence And Limits

The [six-pair comparison](../report-only-validation.md#completion-wait-follow-up)
retained its predefined findings with 33.47% lower aggregate total tokens.
It covers four known synthetic case types and includes three repetitions of one
normal refactor, not independent external validation. Earlier failed comparisons
remain in the record. Do not promote this result to a marketing savings guarantee.

Dynamic module selection can omit a concrete policy file. Large PRs can exceed
the evidence budget. `complete: false` and omitted counts must remain visible;
they do not certify a clean PR or compensate for a missed critical finding.

## Remaining Gates

- [ ] Resolve or explicitly constrain the dynamic-policy and large-PR evidence gaps.
- [ ] Verify matching review quality and actual usage across the declared supported
  scope, including failures, refusal and first-use consent. Keep all attempts.
- [ ] Pass the complete release gate on the final clean revision and CI on its
  exact head; earlier receipts do not approve later changes.
- [ ] Review the installed package and report-only flow without repository source.
- [ ] Approve prerelease publication to `next`, never `latest`, and verify it from npm.
- [ ] Promote to stable only after its gates pass; synchronize all version pins,
  date the changelog, publish npm, verify installation, then submit the plugin.

Current local receipts belong in [Release validation](../release-validation.md).
Follow the [release runbook](../releasing.md) for publication. No registry token,
tag, GitHub release or directory submission is created by preparing this candidate.
