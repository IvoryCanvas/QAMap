# QAMap 0.5.3

A compatible patch to the local PR review brief. Changed source, test contracts,
reference locations and recovery commands remain visible within bounded output.
QAMap makes no LLM calls and does not upload source. The calling host still uses
model tokens to read the evidence; static analysis does not establish test passes.

## Plugin release notes

QAMap 0.5.3 improves binding-aware caller and test evidence, bounded state/cache/lifecycle hints, parameterized test contracts and recovery of omitted diffs. Optional Git history has time limits and discloses shallow or missing evidence. The plugin requires the matching 0.5.3 CLI. Consent and execution boundaries remain unchanged; tests do not run automatically. No new token, speed, cost or review-quality improvement has been measured for this version.

## Changes

- Distinguish direct calls, callback values, types and unresolved lexical bindings.
  Keep source coordinates without inventing callers or executed coverage.
- Retain bounded state-write, shared Map and resource-lifecycle evidence with
  their uncertainty and ownership exclusions. These are review hints, not proved
  state machines, memory leaks or cache faults.
- Limit reference detail before dropping small source and test diffs. Keep
  explicit omissions and larger-budget recovery guidance.
- Bound optional history reads, disable lazy fetching and exclude synthetic
  whole-tree changes at shallow history boundaries.
- Collect multiline and tagged parameterized test declarations and supported
  test modifiers without executing or expanding parameter rows.
- Give omitted untracked files a quoted no-index recovery command and explain
  Git's difference exit code.
- Keep the npm, CLI and plugin versions aligned; generate separate OpenAI and
  Claude review bundles, field sheets and a reviewer guide from maintained data.

See the [complete changelog](../../CHANGELOG.md#053---2026-11-06).

## Compatibility and limits

The CLI, consent choices and additive `qamap.qa` / `qamap.qa.handoff` v1 contracts
remain compatible. The bundled instructions require `@ivorycanvas/qamap@0.5.3`.
Installation is separate from consent to analyze, execute tests or modify files.

Sparse test-body-only edits, type-test files such as `.test-d.ts`, dynamic
titles and aliases are not completely collected. Large diffs may omit important
assertions; read the disclosed recovery paths and the original source. No
collection count is an execution count or complete coverage measurement.

[#317](https://github.com/IvoryCanvas/QAMap/issues/317) remains an unresolved
historical instrumentation intermittency. A passing release gate does not
establish its root cause. Previously published host comparisons are measurements
of earlier builds, not measurements of 0.5.3.
