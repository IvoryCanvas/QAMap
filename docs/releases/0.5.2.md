# QAMap 0.5.2

A patch to the local pull-request review brief introduced in 0.5.1. Removed
behavior, change signals and evidence the brief cannot fully show stay visible
to the reviewer. QAMap makes no model calls or source uploads; a coding agent
still uses model tokens to invoke it and interpret the returned evidence.

The README describes a previously measured build that became 0.5.2, not a fresh
measurement of the released package. The results include the cases that favored
standalone review, host variance and post-hoc design limits.

## Changes

- Preserve removed lines before reference excerpts, label heuristic change
  signals, and list every incompletely shown file with recovery commands.
- Highlight rewritten guards, dropped waits, error handling, unassigned fields
  and callers that may need to handle a new throw. Report name matching and
  untraced references without presenting them as execution proof.
- Keep the brief in the foreground and recover omitted diffs. Packaged review
  instructions ask the host to inspect complete changed functions when hunks
  leave out relevant behavior and check the base before making definite claims.
- Avoid client QA scenarios from server-only changes, resolve dotted module
  names, and keep joined nouns in one flow stage.
- Reuse repository walks, import graphs and large-monorepo index caches; preserve
  changed files and nearby configuration under index limits.
- Install the repository marketplace with `/plugin marketplace add IvoryCanvas/QAMap`
  and `/plugin install qamap@ivorycanvas`; the CLI remains a separate installation.
- Provide the isolated directory package, listing links and paired installation
  guides. Directory publication remains separate from npm publication.
- Lead both READMEs with recorded results and their limitations. Tests check the
  token totals against the committed measurement data.
- Let fork PRs use their own branch names and receive maintainer label notes,
  while retaining title, template and confirmation checks.
- Set the post-release smoke default to the previously published 0.5.1 package.
- Bound coverage worker concurrency while keeping every test and coverage floor.
  Benchmark diagnostics distinguish timeouts from output-buffer failures without
  treating a failed command as a successful compact handoff.

See the [complete changelog](../../CHANGELOG.md#052---2026-10-12).

## Compatibility

The CLI commands, `qamap.qa` and `qamap.qa.handoff` v1 schemas, saved review-mode
preferences and consent behavior remain compatible. The packaged skills require
the matching 0.5.2 CLI. Existing project instructions change only when setup is
run again, without replacing user-authored guidance. Installation does not grant
permission to analyze, execute tests or modify the project.

## Measured Results

The external comparison used 42 public PRs from 12 open-source projects, Claude
Code CLI 2.1.292 and one fixed model. These are host usage receipts, not QAMap
model calls or billing measurements.

| Measure | Standalone | Build that became 0.5.2 |
| --- | ---: | ---: |
| Sum of per-PR median total tokens | 86.1M | 48.6M (-44%) |
| PRs with fewer QAMap-arm tokens | - | 35 of 42 |
| Blind preference, 36 PRs (4 ties) | 18 | 14 |
| Valid findings in the paired grades | 19 | 16 |
| Runs starting tests or installs despite static-review instructions | 5 of 48 | 0 of 48 |
| Later-fixed regressions, 12 runs: found + partly found | 3 + 0 | 5 + 5 |

Preference was not statistically conclusive (p = 0.60). The build was designed
after reading these PRs, so none of the rows is independent evidence. Codex was
not measured. The recorded candidate precedes the joined-noun flow fix: 38 of 42
briefs match byte for byte; four differ in a flow line, and one also has a lower
confidence label. This does not establish a new host measurement of 0.5.2.

See the [validation record](../release-validation.md) and
[external protocol, results and limits](../../test/benchmarks/review-host/external/RESULTS.md#second-re-measurement).

## Remaining Limits

- Token savings are smaller than 0.5.1 in the matched comparisons. On the internal
  19-case suite with CLI 2.1.292, 0.5.1 saved 65.4% and the candidate 54.6%. On the
  earlier 24-public-PR study with CLI 2.1.291, the figures were 51.8% and 45.1%.
  Different host versions are separate measurements, not one pooled result.
- The earlier CLI 2.1.291 studies recorded six incorrect findings against
  standalone's fifteen; this is not the later CLI 2.1.292 finding count. The
  later-fixed regression row above is from CLI 2.1.292.
- One host and one model, author-informed design and limited repetitions do not
  establish a general savings guarantee or superiority in bug finding.
- Dynamic dispatch, injection and string-built paths can hide references. An
  omitted-file list is a recovery map, not proof that review is complete.
- Briefs and QA plans are review evidence, not product specifications or executed
  tests. A person decides whether behavior is intended or broken.
